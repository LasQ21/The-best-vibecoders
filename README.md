# Детектор підозрілих тендерів Prozorro

Сайт на Streamlit, який переглядає публічні закупівлі з Prozorro і показує, які тендери варто перевірити першими. Кожен тендер отримує бал від 0 до 100: він складається з чотирьох простих правил («червоних прапорців») і оцінки аномальності від моделі машинного навчання. Поруч із балом завжди є пояснення українською, чому тендер потрапив у список. Бал означає «подивіться уважніше», а не «тут порушення».

## Запуск

Потрібен Python 3.11 або новіший.

```bash
pip install -r requirements.txt
```

```bash
streamlit run app.py
```

Дані вже лежать у репозиторії, інтернет для запуску не потрібен.

## Дані

Джерело: публічний API Prozorro (`https://public-api.prozorro.gov.ua/api/2.5/tenders`).
У репозиторії лежить знімок від 15.11.2026: 17 981 цивільний тендер, змінений за останні 6 місяців (15.05–15.11.2026), зі статусом `complete` або `active.awarded`. Тендери оборонних замовників (`defense`, `special`) і тестові до знімка не входять.

| Файл у `data/` | Рядків | Що всередині |
| --- | --- | --- |
| `tenders.csv` | 17 981 | по рядку на тендер: замовник, процедура, суми, строки, кількість учасників, переможець |
| `items.csv` | 70 125 | позиції тендерів: опис, код CPV, кількість, одиниця, ціна за одиницю |
| `awards.csv` | 21 564 | рішення про переможців, зокрема за лотами |
| `cpv.csv` | 1 895 | довідник кодів CPV з назвами |
| `feed_state.json` | | час знімка і курсор стрічки змін для дозавантаження |

Процедури: `priceQuotation` 7 306, `aboveThreshold` 6 372, `reporting` 3 500, `belowThreshold` 803. Перші три конкурентні; `reporting` — це прямий договір, там учасників і строків подачі немає, тому прапорці для нього завжди 0.

Реальну ціну за одиницю мають 20 511 позицій із 70 125 (`price_source` дорівнює `contract_item` або `tender_item`). Ціни, отримані діленням суми на кількість (`estimated_from_award`), у порівнянні не беруть участі.

## Прапорці

Пороги задані константами вгорі [`flags.py`](flags.py), кожне правило в окремій функції.

| Прапорець | Коли спрацьовує | Спрацювань на знімку |
| --- | --- | --- |
| `flag_price`, переплата | ціна за одиницю щонайменше вдвічі вища за медіану для того самого товару. «Той самий товар» — це той самий профіль каталогу Prozorro, одиниця виміру і режим ПДВ; у групі має бути не менше 20 позицій | 113 |
| `flag_single_bid`, один учасник | у конкурентній процедурі подано одну пропозицію | 7 829 |
| `flag_repeat_winner`, постійний переможець | тендер виграв найчастіший постачальник замовника, який забрав не менше 40% його конкурентних тендерів; у замовника таких тендерів не менше 20 | 149 |
| `flag_short_period`, короткий строк | строк подачі коротший за 10-й перцентиль для свого типу процедури (на знімку: 7,35 дня для `aboveThreshold`, 2,51 для `belowThreshold`, 2,39 для `priceQuotation`) | 1 367 |

Уточнення в поясненнях:

- До переплати дописується оцінка суми: різниця між ціною і медіаною, помножена на кількість, по всіх позиціях тендера з прапорцем.
- Якщо товар рахується штуками, а ціна вища за медіану в 10 разів і більше, до пояснення додається «перевірити фасовку»: часто це упаковка проти ампули чи таблетки, а не переплата.
- Якщо учасник один і ціна знизилась менш ніж на 1% (або не знизилась зовсім), це дописується до пояснення.
- Якщо в замовника з одним учасником проходить не менше 80% конкурентних тендерів (і їх не менше 20), це теж дописується: одиничний випадок і система — різні речі.

Для сторінки цін є окрема таблиця рівня позицій, `flags.item_price_ratios(items)`. Позиції без профілю каталогу в ній порівнюються грубо, за кодом CPV; прапорець за таким порівнянням не ставиться, бо в одному коді CPV лежать зовсім різні товари.

## Підсумковий бал

Ваги лежать у [`scoring.py`](scoring.py), їхня сума 100:

| Складова | Вага |
| --- | --- |
| переплата | 30 |
| один учасник | 20 |
| постійний переможець | 20 |
| короткий строк | 10 |
| оцінка моделі (`ml_score` від 0 до 1) | 20 |

Кожна складова має значення від 0 до 1, тож тендер з усіма прапорцями на максимумі і `ml_score = 1` отримує 100. Два прапорці важать по-різному залежно від сили сигналу:

- Переплата: ціна ×2 дає половину ваги, ×10 і більше дає повну (шкала логарифмічна). З позначкою «перевірити фасовку» вага не перевищує половини, інакше верх списку займуть ліки, де ампулу порівняли з упаковкою.
- Один учасник: від половини до повної ваги, залежно від частки таких тендерів у замовника.

Тендером «з високим балом» вважається той, що набрав 40 і більше: на знімку таких 171, близько 1%. Якщо модель недоступна, бал рахується лише з прапорців і масштабується до тих самих 0–100.

## Машинне навчання

[`ml.py`](ml.py) навчає `IsolationForest` (200 дерев, `random_state=42`) на конкурентних тендерах. Модель дивиться на всі ознаки разом: логарифм очікуваної вартості, зниження ціни переможцем, кількість учасників, строк подачі, частку найчастішого переможця в замовника, кількість позицій, тип процедури і категорію закупівлі. Результат зводиться до `ml_score` від 0 до 1, де 1 — найбільш нетиповий тендер; для `reporting` він дорівнює 0. Завдяки фіксованому `random_state` бал не змінюється між запусками.

Для тендерів з `ml_score` від 0,5 модель пояснює оцінку: називає одну-дві ознаки, які відхиляються від типових для цього типу процедури щонайменше на два стандартних відхилення, наприклад «переможець дуже часто виграє в цього замовника (51% проти типових 9%)». На знімку таке пояснення мають 877 тендерів.

## Автооновлення

[`updater.py`](updater.py) читає стрічку змін Prozorro від курсора, збереженого в `data/feed_state.json`, відбирає цивільні тендери тих самих типів і статусів, що й у знімку, і завантажує їхні повні документи (для `priceQuotation` ще й договори, бо ціни позицій є лише там). На кожен запит є до 4 спроб зі зростаючою паузою, тендери завантажуються в 4 потоки. Зараз у модулі є лише мережева частина; запису нових тендерів у `data/*.csv` ще немає.

`data_loader.py` читає і початкові файли, і файли, перезаписані через pandas (з датами у форматі `2026-06-17 11:37:14+00:00`).

## Структура

```
data/*.csv
  └─ data_loader.load_data()                    → tenders, items, awards
       └─ scoring.score_tenders(tenders, items, awards)
            ├─ flags.compute_flags()            → прапорці, price_ratio, пояснення
            ├─ ml.anomaly_scores()              → ml_score, ml_reason
            └─ одна таблиця з балом для сайту
                 └─ app.py                      → сайт; графіки з charts.py
```

| Файл | Що робить |
| --- | --- |
| `data_loader.py` | читає CSV: ЄДРПОУ й ідентифікатори як рядки, дати в UTC |
| `flags.py` | чотири прапорці з поясненнями, порівняння цін на рівні позицій |
| `ml.py` | оцінка аномальності з поясненням |
| `scoring.py` | підсумковий бал, цифри для огляду і зведення по замовниках |
| `updater.py` | читання стрічки змін Prozorro |
| `charts.py` | графіки plotly: розподіл цін, постачальники замовника, закупівлі в часі |
| `app.py` | контракт між модулями (назви колонок, перевірки) та інтерфейс сайту |
| `CONTRACT.md` | домовленість про назви функцій, таблиць і колонок |
| `sample_scores.csv` | тестова таблиця балів для розробки сайту; бали в ній вигадані |
| `tests/` | тести прапорців і балу на маленьких вигаданих таблицях |

Перевірка, що таблиці відповідають контракту:

```bash
python -c "import app, data_loader; app.validate_tables(*data_loader.load_data())"
```

Тести:

```bash
python -m unittest discover tests
```
